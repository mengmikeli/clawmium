# Plan — `/auto` max steps config (CLI + `.env` default)

Date: 2026-02-18
Scope: `src/cli/handlers/session.ts`, `src/cli/repl.ts`, `src/auto/runner.ts`, `.env.example`, `README.md`

## Goal

Make `/auto` step limit configurable from both:
1. **CLI flag** (per run override)
2. **`.env` value** (default for all runs)

with this precedence:

1. CLI flag value (highest)
2. `.env` default
3. hardcoded fallback (current default)

---

## Desired UX

### Default behavior (no flag)

```bash
/auto check my water bill
```

- Uses `AUTO_MAX_STEPS` from `.env` if present.
- If missing/invalid, uses fallback default (`10`).

### Override behavior (flag)

```bash
/auto check my water bill --max-steps 20
```

- Uses `20` for this run only.
- Does **not** mutate `.env`.

### Optional short form

```bash
/auto check my water bill -s 20
```

- Same as `--max-steps 20`.

---

## Validation rules

For both `.env` and CLI values:

- Must be integer.
- Must be within safe bounds, proposed: `1..100`.
- Invalid CLI value: show usage error + do not start auto.
- Invalid `.env` value: warn once and fall back to `10`.

Rationale: prevent runaway loops while allowing long tasks.

## Implementation plan

## 1) Add config parser for max steps

### Where
- `src/cli/repl.ts` (private helper near other utility methods), or a small helper module if preferred.

### Add
- `parseAutoMaxStepsFromEnv(): number`
  - Reads `process.env.AUTO_MAX_STEPS`.
  - Applies integer + bounds validation.
  - Returns validated value or fallback `10`.

## 2) Extend `/auto` command parsing

### Where
- `src/cli/handlers/session.ts` in `handleAuto()`.

### Change
- Parse `arg` into:
  - `goal` text
  - optional `maxSteps` from `--max-steps N` or `-s N`
- On parse failure, show:
  - `usage: /auto <goal> [--max-steps N]`

### Notes
- Keep parsing minimal and deterministic (no extra dependency).
- Preserve existing behavior when no flags are provided.

## 3) Allow `runAutoMode()` to accept config override

### Where
- `src/cli/repl.ts`

### Change
- Update signature:
  - from: `runAutoMode(goal: string)`
  - to: `runAutoMode(goal: string, opts?: { maxSteps?: number })`
- Compute effective value using precedence:
  - `opts.maxSteps ?? envDefault ?? 10`
- Pass into runner:
  - `runAuto(goal, deps, { maxSteps: effectiveMaxSteps }, autoAbort.signal)`

## 4) Keep runner defaults as safety net

### Where
- `src/auto/runner.ts`

### Change
- Keep `DEFAULT_CONFIG.maxSteps = 10` unchanged.
- This remains final fallback in case upstream call omits config.

## 5) Docs and examples

### Update
- `.env.example`
  - Add `AUTO_MAX_STEPS=10` with short comment.
- `README.md`
  - Document `/auto` flag usage and precedence.
  - Add one example command with `--max-steps`.
