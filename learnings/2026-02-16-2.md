## What We Did

### 1. Wired form detection into REPL (`src/cli/repl.ts`)

- Added `detectedForms: DetectedForm[]` to `SessionState`
- Called `detectInteractiveForms(page)` in `_processCurrentPage()`, after login detection but before HN special handling
- `appendSystemChoices()` iterates detected forms, creates `fill` choices with `inputSelector` and `submitAction: "enter"`, deduplicates against LLM-generated fill choices by comparing `fillPlan.inputSelector`
- Login choice appended after form choices (ordering: LLM choices → detected forms → login)

### 2. Fixed Google search: textarea support in form detector (`src/forms/detector.ts`)

**The bug:** Google's search input is `<textarea name="q">`, not `<input>`. The detector only queried `input[...]` elements, so the form was recognized as a search form (because `action="/search"`) but the primary input was never found. The user saw a "Search" choice from the LLM but not from the detector.

**Five edits, one root cause:**

| Location | Before | After |
|----------|--------|-------|
| Primary input query (line 47) | `input[type="search"], input[name*="q"], ...` | Added `textarea[name*="q"], textarea[name*="search"], textarea[placeholder*="earch"]` |
| Type annotation (line 49) | `HTMLInputElement \| null` | `HTMLInputElement \| HTMLTextAreaElement \| null` |
| Selector building (line 51-55) | Hardcoded `input[name="..."]` | `${tag}[name="..."]` where `tag = searchInput.tagName.toLowerCase()` |
| Standalone scan (line 86) | Only `input[...]` selectors | Added `textarea[name="q"], textarea[name*="search"]` |
| Standalone selector (line 92-96) | Hardcoded `input[name="..."]` | Same `${tag}[name="..."]` fix |

**The pattern:** Every place the detector queried for inputs, built selectors, or cast types needed the same `input → input|textarea` expansion. Five edits, but they're all the same conceptual fix applied at each occurrence.

### 3. Fixed tautological label: `Search: "Search"` → `Search this site`

Google's textarea has `aria-label="Search"` but no `placeholder`. The original code only checked `placeholder`, so Google got `"Search this site"` (correct by accident — empty placeholder). After adding `aria-label` fallback, it became `Search: "Search"` (tautological).

**Fix:** If the hint text (placeholder or aria-label) is just the word "search" (case-insensitive), fall back to `"Search this site"`. Descriptive hints like `"Search packages"` still render as `Search: "Search packages"`.

### 4. Navigator error handling (`src/browser/navigator.ts`)

- **Network errors:** `net::` (Chromium) and `NS_ERROR_` (Firefox) patterns in Playwright error messages now throw a user-facing message: `"could not reach {url} — site may be down or URL may be wrong"`
- **HTTP errors:** Response status >= 400 throws `"{url} returned HTTP {status}"`
- **REPL catch sites:** All four navigation paths in the REPL (`/goto`, `/home`, `/home set`, `/demo`) now catch navigator errors and display them via `render.error()` instead of crashing

### 5. Test infrastructure (`src/__test__phase5.ts`)

- **Browser availability check:** `checkBrowser()` pre-flight test; if Chromium can't launch (missing system deps), browser-dependent tests are skipped instead of failing
- **`appendSystemChoices` unit tests:** 7 tests covering form→choice conversion, ordering, dedup by selector, login positioning, non-fill action non-dedup. Tests inline the `appendSystemChoices` logic to avoid importing the full REPL with its heavy dependencies.
- Test count: 66 → 91 assertions (25 new)

## What Went Wrong

- **Assumed `<input>` universally.** The detector was written against standard HTML form patterns where search is `<input type="search">` or `<input name="q">`. Google uses `<textarea>` — a perfectly valid HTML element for text input, just not the conventional one for search. The fix is mechanical, but the lesson is about testing assumptions against real sites, not just spec-compliant examples.

- **aria-label fix created a new bug.** Adding `aria-label` fallback was correct, but it turned a working-by-accident label ("Search this site", because empty placeholder) into a broken one (`Search: "Search"`). The aria-label itself is perfectly fine metadata — the problem was that the label template assumes the hint text is *descriptive* of what you're searching, not just the word "search" again. Two-pass fix: first the data source (aria-label), then the presentation logic (dedup check).

## Top Learnings

1. **Test against real sites, not just spec examples.** The form detector was tested against synthetic HTML (`<input name="q">`) that matched the code's assumptions. Google.com — the most visited search page on the internet — uses `<textarea>`. Synthetic tests prove correctness against your model of the world; real-site testing proves correctness against the actual world. Both are necessary.

2. **Expanding a selector query has a blast radius.** Adding `textarea[...]` to the CSS query was one line, but it touched five locations: the query itself, the TypeScript type, the selector builder, the standalone scan, and the standalone selector builder. When code branches on element type at multiple points, a new element type is a cross-cutting change. A helper function (e.g., `buildSelector(el)`) would have localized the change — worth considering if a third element type ever appears.

3. **Fallback chains can produce correct-by-accident results that break when you add a link.** The original label was `"Search this site"` on Google because `placeholder` was empty — it fell through to the default. Adding `aria-label` as a middle step in the fallback chain produced `Search: "Search"` — technically correct (it *is* the aria-label), but nonsensical to the user. When extending fallback chains, test that the *presentation* is still coherent, not just that the *data* is non-null.

4. **Error swallowing is invisible debt.** The navigator silently caught all navigation errors. This meant network failures, DNS resolution errors, and HTTP 4xx/5xx all looked the same to the user: the page just didn't change. Surfacing errors is simple (`throw` instead of `catch-and-ignore`), but it requires updating every call site. The longer you wait, the more call sites accumulate.

5. **Inline logic in tests avoids dependency chains.** The `appendSystemChoices` tests reproduce the logic rather than importing `Repl`. This means tests don't break when `Repl`'s constructor signature changes, don't need to mock `BrowserEngine` and `LLMProvider`, and run in milliseconds. The tradeoff is that the test logic can drift from the real logic — but for a 15-line function, the drift risk is low and the isolation benefit is high.
