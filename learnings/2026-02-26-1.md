## What Went Wrong

1. **Test API mismatch** — Wrote tests using `m.addNode()` which doesn't exist; actual method is `m.addNavigation()`. Caught on first test run but avoidable by reading the class first.
2. **Orphaned design doc** — `learnings/2026-02-26-0.md` was written during the crawl intelligence design session but never committed with its code. Left as untracked.

## Top Learnings

1. **Prerequisite refactors pay for themselves immediately** — Decoupling history from crawl trees made persistent history trivial. The two-commit approach (refactor, then feature) was cleaner than a combined approach.
2. **Always check the API before writing test code** — `addNode` vs `addNavigation` cost a full test cycle. Read the class interface before consuming it.
3. **Timestamp-based dedup is a simple idempotency mechanism** — For append-only logs with monotonic timestamps, dedup-by-timestamp makes periodic flush idempotent without sequence numbers.
4. **`startIndex` for incremental extraction** — Tracking `lastFlushedCursorIndex` avoids re-extracting the entire cursor. Simple counter, big efficiency win for periodic flush.
5. **Separate "stack" from "history"** — Chrome's tab-back/forward vs chrome://history maps perfectly: ephemeral session navigation vs persistent visit log. Making `/stack` and `/history` serve different purposes eliminated conceptual overlap.
6. **Massive commits can land clean with good test coverage** — The crawl intelligence commit touched 20+ files but all 587+ tests stayed green because each new subsystem had its own test suite.
