## What Went Wrong

### 1. `extraHTTPHeaders` doesn't work for navigation requests
The entire initial approach was wrong. Chromium ignores `extraHTTPHeaders` for document-type (navigation) requests and sends its own `Accept: text/html,...` header. The same curl command with the same header worked perfectly — the difference is that Chromium's network stack overrides Accept for navigation. Only discovered by testing against the real Cloudflare endpoint.

**Fix**: Switched to `context.route('**/*', ...)` with `route.fallback({ headers })`, which intercepts at the network level and actually modifies the wire header.

### 2. Accept header quality values were backwards
First version used `text/markdown;q=0.8` which is *lower priority* than `text/html` (implicit q=1.0). Even if the header reached the server, it would prefer HTML per RFC 7231 content negotiation.

**Fix**: Put `text/markdown` first (implicit q=1.0), demoted `text/html;q=0.9`.

### 3. Sub-resource markdown fragments overwrote main document
Cloudflare's `_server-islands/SocialLinks` endpoints return tiny 100-byte markdown fragments. Since the interceptor stored the *last* `text/markdown` response, these fragments overwrote the 16KB main document markdown.

**Fix**: Added minimum length threshold (200 chars) + keep-longest logic in the interceptor.

## Top Learnings

1. **Browser engines have their own Accept headers for navigation requests** — `extraHTTPHeaders` only works for sub-resource requests (XHR, fetch, images). For document navigation, use `context.route()` with `route.fallback({ headers })` to override at the network level. This is a Playwright/Chromium limitation not documented prominently.

2. **Always test HTTP-level features against real servers** — mocks can't reveal browser engine behavior. The 5-minute curl test passed; the 5-minute Playwright test failed. Real integration tests are worth the network dependency for protocol-level features.

3. **Content negotiation quality values matter** — servers that do proper RFC 7231 content negotiation will serve the highest-quality type. `q=0.8` means "I'll accept it but I'd rather have something else." Put your preferred type first.

4. **Interceptor capture needs filtering for modern sites** — sites make many sub-requests that may return the same content-type as the main document. Keep-longest + minimum-length is a simple heuristic that handles this.

5. **`route.fallback()` is the right Playwright primitive for header modification** — unlike `route.fulfill()` (which requires providing a response) or `route.continue()` (which commits to handling), `fallback()` passes through to the next handler with modified request properties. Clean and composable.
