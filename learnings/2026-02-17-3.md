# Banner fix + strategic checkpoint

## Preamble

A cosmetic fix — ANSI banner art misaligned due to trailing spaces inside color sequences — took 20 minutes but surfaced a useful principle. Then a strategic checkpoint: the infrastructure layer is solid, and the next lever is LLM intelligence.

---

## 1. ANSI art alignment: separate art from padding

The banner bug was trailing spaces baked inside ANSI color sequences. Terminals miscounted the visible width because they couldn't tell ANSI escapes from printable characters. The fix: store the actual visible width per line, compute padding as plain spaces *after* the ANSI string. Tiny change, big principle.

**The rule**: when mixing ANSI escape codes with layout math, never embed whitespace inside colored regions. Keep the coloring and the spacing as separate concerns. This is the same "separate mechanism from presentation" pattern that keeps appearing — ANSI codes are mechanism (color), padding is presentation (layout). Interleaving them creates bugs that are invisible in the source but visible in the terminal.

---

## 2. Cosmetic polish as palette cleanser

Small visual wins (banner animation, progress line cleanup, navSummary styling) are worth doing between heavy architecture sprints. They build user-facing polish incrementally, they're low-risk, and they give you a mental break between structural work.

But they're also detail traps. ANSI alignment alone had 3 frame definitions x 3 lines x length counting to get right. A "quick fix" balloons when you're reasoning about invisible characters.

**Budget them explicitly**: one polish item, then back to the hard problems. Don't let a cosmetic detour turn into a cosmetic sprint.

---

## 3. Strategic checkpoint — infrastructure done, intelligence next

The infrastructure stack is in solid shape:

| Layer | Status |
|-------|--------|
| Browser engine | Launch, show/hide, cookie transfer, crash recovery |
| Navigation | goto, back, forward, history, home, refresh, stack |
| Crawl tree | Node tree, dedup, cursor history, stash, markdown persistence |
| Session persistence | JSON sidecar, auto-resume, auto-save, stash serialization |
| CLI rendering | Progress lines, content boxes, nav summaries, data tables, hints |

This is the mechanism layer — it works, it's tested (500+ assertions across 7 test suites), and it doesn't need more features right now.

**The next lever is LLM intelligence**:

- **Richer `interpret()` output** — current summaries are adequate but generic. The prompts can be tuned per page type: news articles should extract claims and sources, HN threads should surface consensus vs debate, documentation should extract the key API/concept.
- **`/auto` mode** — wire `planAction()` into an autonomous loop. `interpret -> plan -> execute`, human interrupts with Ctrl+C. CityServe demo is the first test case. This is item #6 on the TODO.
- **Content extraction for hostile sites** — anti-bot sites return empty content. Strategies: scroll-to-load (already exists), readability-style extraction, screenshot + vision model as last resort.
- **MCP server** — programmatic interface for other agents. This is item #7 on the TODO.

The mechanism layer is built. Time to invest in the intelligence layer.
