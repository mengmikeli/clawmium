# Crawl Intelligence: Vision, Decisions & Plan

**Date:** 2026-02-26
**Topic:** Rethinking the crawl system — from mechanical recorder to intelligent, agent-managed browsing trails

---

## The Problem

The crawl system has a solid data mechanism — append-only node trees, URL dedup, cursor history, stash, markdown + JSON persistence. But it falls short in five areas:

1. **Tree structure is a rendering artifact** — The `.md` file preserves tree via indentation, but it's not composable. You can't merge two crawl files or map them to a filesystem hierarchy.

2. **No semantic merging or pruning** — Every crawl is an isolated island. Three HN sessions about Rust create three separate trees with no connection. Dead-end branches (404s, immediate backs) clutter the tree.

3. **No intent signal detection** — All crawls treated equally. No classification of "active task the user cares about" vs "idle browsing." GoalContext captures intent within a session but isn't analyzed across sessions.

4. **No content filtering** — No crawl suppression or content classification. Trivial one-off lookups sit alongside important tasks. No sensitive content tagging.

5. **No trail completion intelligence** — Crawls are "active" or "ended" (`/crawl end`). No semantic understanding of "task done" (confirmation page) vs "overdue" (bill past due) vs "stale" (forgotten research).

### Root cause

There's no intelligence layer between the mechanical crawl recorder and the user:
```
Raw events → CrawlNode tree → flat markdown   (what exists)
Raw events → CrawlNode tree → INTELLIGENCE → curated, living knowledge   (what's needed)
```

---

## Key Mental Model: Crawl Trees = Browser Tabs

The user's analogy: crawl trees are Clawmium's equivalent of browser tabs and tab groups. The agent manages them the way a human manages their tab bar:

- **Merge** = dragging tabs into one group ("these three HN sessions are all Rust research")
- **Prune** = closing tabs you don't need ("I hit a 404, went back, tried two dead ends")
- **Close** = closing a tab group when done ("I paid the bill")
- **Move/regroup** = moving a tab between groups ("this tab belongs in that group")

There is no separate "trail" abstraction. The crawl tree IS the unit. Intelligence is applied TO the tree — it becomes a living, malleable structure.

## Decisions Made

### Homepage UX → Hybrid
Pinned active tasks at top (like pinned tabs), ranked feed of other trails below (like a timeline). Compact + expandable — scan quickly, drill in on selection.

### Classification timing → Both
Light heuristic tagging during session (zero LLM cost) + LLM reflection on shutdown for ambiguous crawls + periodic sweep on startup for stale open crawls.

### Proactivity → Startup only
Show trail status when launching clm (homepage dashboard). Stay quiet during browsing sessions — don't interrupt flow.

### Content filtering → Both noise + safety
Noise reduction (hide trivial one-off lookups from homepage) AND content safety tagging (sensitive content flagged, optionally hidden).

### Merge granularity → Both, graft default
Whole-tree grafting as default operation (tree B becomes subtree of tree A). Branch-level moves available for power users. Both use existing `detachSubtree()`/`attachSubtree()` primitives.

### Who executes → Agent auto-manages
Agent autonomously prunes dead ends, merges related trees, updates lifecycle states. User can review, undo, or override. No confirmation prompts for routine operations.

### Completion model → Multi-state lifecycle

| State | Meaning | Detection |
|-------|---------|-----------|
| **open** | Active, unfinished | Default state |
| **done** | Task completed | Confirmation page, data extracted matching goal |
| **overdue** | Time-sensitive, past due | Goal set but abandoned, due date signals |
| **stale** | Forgotten, no urgency | lastAccessed > 48h, no urgency signal |

### Tree management timing → Shutdown + periodic sweep
Light pruning + classification at session shutdown. Deeper cross-tree analysis (merges, stale detection) as startup sweep before homepage render.

### Token budget → Hybrid
Heuristics for real-time tagging (zero cost). LLM only on shutdown for crawls with heuristic confidence < 0.7. ~200-500 tokens per crawl.

## Architecture: What Changes

### New types (`src/crawl/classify.ts`)
- `CrawlMeta` on `Crawl` — lifecycle, tags, pinned, noise, sensitive, merge history
- `NodeClassification` on `CrawlNode.metadata` — live/dead/pruned with reason
- `CrawlLifecycle` = "open" | "done" | "overdue" | "stale"
- `CrawlTag` = "research" | "lookup" | "task" | "exploration" | "reference" | "sensitive"

### New CrawlManager methods
- `getLeafNodes()`, `findNodes(predicate)`, `getNodeStats()`
- `removeSubtree(nodeId)` — detach + delete entire subtree
- `setCrawlMeta()` / `getCrawlMeta()` — crawl-level metadata

### New files
- `src/crawl/classify.ts` — heuristic + LLM classification engine
- `src/crawl/prune.ts` — dead-end detection + removal
- `src/crawl/merge.ts` — candidate detection + graft/move operations
- `src/cli/homepage.ts` — homepage data building + rendering

### SessionEnvelope v4
- Adds `CrawlMeta` serialization
- `NodeClassification` flows through existing metadata serialization
- v3 backward compat via backfill

### Startup flow replacement
```
BEFORE:  "Resume previous session? (y/n)"
AFTER:   Homepage dashboard with pinned/active/done/stale sections, numbered for selection
```

## Implementation Phases (MVP first)

1. **Phase 1: Data model + heuristic classifier** — types, node/crawl classification, shutdown hook
2. **Phase 4: Homepage dashboard** — the visible UX change, replaces resume prompt
3. **Phase 2: Pruning** — `/crawl prune` + auto-prune on shutdown
4. **Phase 3: Merging** — `/crawl merge` + candidate detection + graft
5. **Phase 5: LLM classification** — shutdown reflection + startup sweep

Phase 1 + 4 is the MVP: classified crawls shown on a dashboard.

---

## Design Principles Applied

- **Separate facts from judgment**: Mechanical layer records (nodes, timestamps). Intelligence layer interprets (lifecycle, tags, merge candidates). Never hardcode semantic rules at the recording layer.
- **Simple foundations absorb new layers**: `CrawlMeta` is optional on `Crawl`. `NodeClassification` is optional on `CrawlNode.metadata`. All existing code continues to work with unclassified crawls.
- **Agent manages, human overrides**: Auto-prune, auto-merge, auto-classify. But `/crawl pin`, `/crawl done`, `/crawl merge` give the human explicit control.
