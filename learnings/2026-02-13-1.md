# 2026-02-13-1: From Localhost to the Real Web

## What We Did

Built Clawmium — an agent-first, human-second browser — from zero to a working prototype in a single session. The project uses headless Chromium (via Playwright), an LLM (GPT-4o/Claude) for page interpretation, and a CLI REPL for human interaction. The core thesis: browsers should serve agents first and render pixels only on demand.

### Phases completed

- **Phase 1** — CityServe mock government website (Express, cookie auth, JSON APIs)
- **Phase 2** — Playwright browser engine (headless-first, show/hide with cookie transfer, network interception)
- **Phase 3** — LLM integration (OpenAI + Anthropic providers, structured JSON prompts for page interpretation and data extraction)
- **Phase 4** — CLI REPL (slash commands, numbered choices, free-text conversation, auth handoff, data saving)

The CityServe demo worked cleanly: launch headless browser → navigate to localhost → detect login page → prompt credentials in CLI → capture session cookies → intercept `/api/water-bill` JSON → extract and display structured data in an ASCII table → save to disk.

Then we stress-tested on real websites (NYT, Hacker News, personal blogs, Google DeepMind) and spent the rest of the session fixing everything that broke.

## What We Learned

### 1. Design assumptions break on real websites

The CityServe demo had clean APIs, predictable DOM, no anti-bot detection. The moment we navigated to nytimes.com, five things broke simultaneously:

- `waitUntil: 'networkidle'` hung forever (ad networks never stop loading)
- The network interceptor captured `/api/` URLs from third-party ad domains, flooding the terminal
- `findRelevantApiData()` picked up JWT tokens from ad networks as "relevant structured data"
- `/show` crashed because relaunching the browser and navigating to NYT timed out
- No recovery mechanism existed after a browser crash — all subsequent commands failed

**Takeaway:** Always test with real-world inputs early. The gap between "works on localhost" and "works on the internet" was the entire debugging session. Build the fallback chain from day one.

### 2. Agent-first doesn't mean navigation-only

The original LLM prompt said "list clickable options as choices." The LLM dutifully turned every page — blog posts, articles, about pages — into a list of navigation links. The actual content (the blog post text, the article body, the author bio) was completely invisible to the user.

A blog post about macOS window resizing showed up as:
```
[1] Visit home page
[2] Read about the author
[3] View macOS category
[4] Read previous post
```

The fix was a prompt rewrite: "CONTENT FIRST — the summary field should capture what the page actually says." We also added a `"content"` page type distinct from `"navigation"`, and changed the rendering to always show the summary before choices.

**Takeaway:** An agent-first browser that only navigates is just a worse browser. The value proposition is in reading, reasoning about, and conversing about content — not in listing links.

### 3. State management is harder than content parsing

The most persistent bugs were all about stale state:

- `userGoal` stayed as "check my water bill" after `/goto nytimes.com`, causing the LLM to hallucinate water bill data from NYT content
- `currentInterpretation` was overwritten by free-text LLM responses, so previously shown numbered choices became unreachable
- `rl.close()` during auth handoff fired the readline `close` event, which called `shutdown()`, which closed the browser before auth could complete
- `/back` re-interpreted the page from scratch via the LLM, producing different choices in a different order

Each required a dedicated mechanism: goal reset on external navigation, `previousInterpretation` with "did you mean?" confirmation, `closingForAuth` flag, page history stack.

**Takeaway:** For stateful interactive systems, inventory every piece of mutable state and trace what happens to it in every transition. The happy path is obvious; the state corruption is where the bugs live.

### 4. Build the fallback chain, not the happy path

A recurring pattern emerged across every component:

| Component | Ideal | Fallback 1 | Fallback 2 |
|-----------|-------|------------|------------|
| Page load | `networkidle` (15s) | `domcontentloaded` (15s) | Continue with whatever loaded |
| Content extraction | Intercepted network JSON | Scroll-to-load + re-extract DOM | Sparse content warning |
| Browser state | `isAlive()` check | `recover()` — relaunch headless | Error message to user |
| Click navigation | `page.click(selector)` | Get `href` and `nav.goto()` | Detect anchor link, skip |
| Auth handoff | CLI credential entry | Retry up to 3 times | Cancel and return to prompt |

The happy path was maybe 20% of the code. The resilience — timeouts, try/catch, fallbacks, guards — was 80%.

**Takeaway:** Design the degradation path before the success path. Ask "what happens when this fails?" for every async operation.

### 5. Prompts are product decisions

Each prompt change had a direct, visible impact on the user experience:

| Prompt change | UX impact |
|---------------|-----------|
| "List clickable options" → "CONTENT FIRST: summarize what the page says" | Blog posts became readable instead of link directories |
| Added "Do NOT fabricate content from the URL alone" | Stopped hallucinated article titles from empty pages |
| Added "answer the follow-up question, don't re-describe the page" | Free-text conversation started working |
| Added `"content"` page type with filtered choices | Navbar chrome (Home, About, Archives) stopped dominating choices |
| Added conversation context parameter | "Why is this important?" got a real answer instead of a page re-summary |

**Takeaway:** In an LLM-driven product, the system prompt IS the product spec. Treat prompt engineering as UX design, not backend implementation.

### 6. Terminal UI has its own class of bugs

Several issues were specific to building a CLI application with raw terminal I/O:

- Double echo on credential input (readline and raw stdin both active)
- Password characters visible (readline echoing before raw mode took over)
- Backspace deleting the prompt character (readline didn't know prompt width)
- ANSI escape codes have zero display width but non-zero string length, breaking box alignment
- `Ctrl+C` handling required careful coordination between readline SIGINT, AbortController, and the shutdown guard
- Double Ctrl+C detection needed a 2-second window (1 second was too tight with I/O processing overhead)

**Takeaway:** Terminal I/O state machines are deceptively complex. Raw mode, readline, and process signals interact in non-obvious ways. Test keyboard input edge cases early.

## Possible Improvements (Next Session)

### High priority

1. **HN comment threads** — Clicking an HN story goes to the external link. No way to read the HN discussion, which is arguably the most valuable content. Detect HN item pages (`item?id=...`) and present comments as content.

2. **Content box rendering polish** — ANSI codes in the title line break right-edge alignment. The `dataTable` renderer can break on very wide values. Small but visible.

3. **Smarter goal tracking** — Free text follow-ups work on the current page, but goals don't carry across navigations intelligently. If you say "find articles about AI" on HN, then click into one, the agent doesn't know you're browsing for AI articles specifically.

### Medium priority

4. **Session persistence** — Session logs save to `~/clm/` but there's no way to resume a session or review past extractions. A `/history` command or session replay would add value.

5. **Anthropic provider testing** — All real-world testing was done with OpenAI. The Anthropic provider hasn't been stress-tested with the new `conversationContext` parameter or content-first prompts.

6. **`max_tokens` tuning** — Currently 1024 for interpret calls. Longer articles may get truncated summaries. Should be adaptive based on input length.

### Lower priority

7. **Stealth mode for anti-bot sites** — `playwright-extra` + `puppeteer-extra-plugin-stealth` could bypass basic bot detection (NYT, OpenAI). Arms race territory but would expand the usable web surface.

8. **CLAUD.md update** — The original design spec is now outdated in several areas (mentions `chalk`, `ora`, Option A for headless toggle, "No real website support"). Should reflect the current architecture.

9. **Page content deduplication** — When the same page is re-interpreted (via free text follow-up), we send the full page text again. Could cache and send only the conversation delta.
