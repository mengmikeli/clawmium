## What We Actually Did

Instead of features, we went deep on a fundamental architecture problem: **who owns the current URL?** This spawned the REPL stack refactor — making `state.currentUrl` the single source of truth, replacing the browser as authority on "where we are."

Concrete changes:
- Replaced `ensureBrowser()` with `syncBrowser()` (3-point check: alive? responsive? correct URL?)
- Made `/back` and `/forward` pure stack mutations — no browser access
- Set `state.currentUrl` explicitly after every `nav.goto()`, never reading from `page.url()`
- Extracted `recoverBrowser()` from inline recovery logic
- Added `captureSnapshot()` / `restoreSnapshot()` for clean stack operations
- Renamed `recoveryUrl` → `currentUrl` (cleanup after refactor)
- Added `/url` debug command showing REPL vs browser state
- Added `/home` with URL persistence, `/refresh`, `/forward`
- Fixed double recovery warning message

Also polished:
- Content box rendering (ANSI alignment — turned out the existing code was already correct)
- `/url` display with sync indicator

## What Went Wrong

- **`trackUrl()` was a trap** — Original approach read `page.url()` after operations to track position. Failed silently after `/show` because the headed page was alive but on a stale URL. The function looked correct but produced wrong data in the one scenario that mattered most.
- **`page.url()` lies** — After `/show` transfers cookies to a headed browser, the old headless page object is dead but still returns its last URL. After `/back` through cached stack, `page.url()` returns the browser's last real position, not the REPL's stack pointer. Reading it to set state creates a corruption loop.
- **Recovery needed recovery** — The error handler in `startReadline()` called recovery, which printed a warning, but the handler also printed its own warning. Two "browser disconnected" messages for one event.
- **Variable name obscured the design** — `recoveryUrl` was named for its original narrow purpose (where to go after crash recovery). As the refactor expanded its role to "the REPL's canonical position," the name masked the architectural significance. The rename to `currentUrl` wasn't cosmetic — it clarified the design to both humans and LLMs reading the code.

## Top Learnings

1. **The browser is a servant, not the source of truth.** This inverts the normal browser model. The REPL stack owns position; the browser syncs on demand. This is what makes `/back` work with a dead browser.
2. **Never read mutable external state to set your own state.** `page.url()` is browser state that can be stale, dead, or wrong. Setting `currentUrl = page.url()` is a category error — importing uncertainty into your source of truth.
3. **"Sync on demand" beats "track continuously."** Deleting `trackUrl()` (continuous) and adding `syncBrowser()` (on-demand before operations) was simpler and more reliable. The browser catches up when needed, not after every mutation.
4. **Feature work takes a back seat to foundation work.** We planned content features but spent the session on state management. The right call — building features on a broken foundation creates harder-to-debug problems later.
5. **Name things for what they are, not what they were.** `recoveryUrl` → `currentUrl` changed zero behavior but made the architecture legible. Future sessions (human and LLM) will immediately understand the design intent.
