### Interactive Form Detection (`src/forms/detector.ts`)
- `detectInteractiveForms()` — DOM scan for search boxes, filter forms, standalone inputs
- Skips password-containing forms (login handled by auth system)
- Classifies as `search`, `filter`, or `input` based on heuristics (type="search", name contains "q"/"search", placeholder text, aria-label, form action URL)
- Standalone `<input>` outside `<form>` tags detected as fallback
- Capped at 3 forms per page

### Goal Context (`src/cli/goals.ts`, `src/llm/provider.ts`)

## What Went Wrong

- **`HTMLImageElement.width` pitfall (again)** — HN comment depth is calculated from the indent spacer image's `width` attribute. In `page.evaluate()`, `img.width` returns the *rendered* width (0 for broken images in headless), not the HTML attribute. Had to use `getAttribute("width")` in production code and serve a real 1x1 GIF in tests. This trap was already documented in MEMORY.md from a previous session — reading the memory file would have saved debugging time.

- **esbuild `__name()` wrapping** — Named arrow functions inside `page.evaluate()` callbacks get wrapped by esbuild/tsx with a `__name()` helper that doesn't exist in the browser context. Hit this in the form detector. Solution: use anonymous functions or inline the logic directly. Also already in MEMORY.md.

- **No formal planning step** — Jumped straight into HN comments without checking the TODO or reviewing yesterday's next steps in a structured way. The reflection ritual was conceived mid-session as a solution to this — we were building the tool we needed while experiencing the problem it solves.

- **Anthropic testing deferred again** — Third session in a row where Anthropic provider testing is on the list but doesn't get done. Lower priority keeps getting bumped by more tangible feature work.

## Top Learnings

1. **Read your own memory before starting.** Both the `HTMLImageElement.width` and esbuild `__name()` traps were already documented in MEMORY.md. A 30-second scan at session start would have prevented re-discovery. The `/standup` ritual exists to force this habit.

2. **A ritual beats a reminder.** "Remember to review yesterday's notes" is a thought that evaporates. A skill that triggers on `/reflect` and `/standup` with a defined checklist turns intention into action. Tools shape behavior better than intentions.

3. **Deep-copy nested state in snapshots.** `GoalContext` has a `breadcrumb` array — spreading the outer object (`{ ...gc }`) shares the inner array reference. Stack navigation corrupts silently until you push/pop and realize two snapshots share the same array. Always spread nested collections: `{ ...gc, breadcrumb: [...gc.breadcrumb] }`.

4. **Form detection must exclude auth forms.** The form detector and auth detector operate on the same page. Without the `password` field filter, search inputs get mixed with login inputs. Domain boundaries between subsystems (forms vs auth) need explicit guards, not just convention.

5. **`fillPlan` keeps the LLM in control without giving it execution.** The LLM decides *what* to fill and *how* to submit (Enter vs click), but the REPL executes the plan. This is the same pattern as navigation choices — the LLM is the strategist, the code is the executor. Keeps the boundary clean.

6. **Test with real resources, not mocks of browser internals.** The 1x1 GIF trick for HN indent images works because it gives the browser a real resource to render, so `getAttribute("width")` returns the actual HTML attribute. Mocking `img.width` would test the mock, not the code.

7. **Persistent TODO > embedded next-steps.** Next steps buried at the bottom of learning files require knowing which file to read and parsing narrative text. A dedicated `TODO.md` with priority tags is scannable in 5 seconds.
