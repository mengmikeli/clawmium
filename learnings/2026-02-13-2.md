# 2026-02-13-2: Rewriting the Spec to Match Reality

## What We Did

Rewrote `CLAUD.md` to reflect the actual implemented architecture. The original spec was preserved as `learnings/2026-02-13-0.md` before overwriting.

## Why

The original CLAUD.md was a design document written before any code existed. It was authored in a Claude.ai conversation as a blueprint for building Clawmium. After a full build session that included significant real-world stress testing, the implementation had diverged from the spec in meaningful ways — not because the vision changed, but because the spec's assumptions didn't survive contact with real websites.

A spec that describes what you *planned* rather than what you *built* becomes misleading. Anyone reading CLAUD.md (including future LLM sessions) would get wrong mental models about how auth works, what libraries are used, or whether real websites are supported.

## Key Changes and Why

**Auth flow** — The spec described a browser-popup flow ("open browser, human types credentials, agent watches for URL change"). We built CLI-based auth instead (raw stdin, password masked, form submitted via Playwright). The browser window never opens. The spec was wrong about a core user-facing interaction.

**Real website support** — The spec listed "No real website support (mock only)" as a non-goal. We explicitly built and debugged real website support. This was the single biggest area of divergence — the entire second half of the build session was about making HN, NYT, and blogs work.

**Content-first philosophy** — The spec said "list clickable options as choices." The implementation learned (the hard way) that content summarization matters more than navigation listing. This was a fundamental product insight that the spec had no concept of.

**Tech stack** — The spec listed `chalk`, `ora`, `@inquirer/prompts`. None were used. All terminal output is raw ANSI escape codes and Node's readline. Small detail, but someone reading the spec would install the wrong dependencies.

**State management** — The spec had no concept of page history stacks, previous interpretation tracking, conversation context, goal reset on external navigation, or guard flags. These emerged from debugging real usage patterns and represent the majority of the REPL's complexity.

**Resilience patterns** — The spec described happy paths. The implementation is 80% fallback chains, timeouts, and crash recovery. The resilience table in the new CLAUD.md captures what actually makes Clawmium work on the real web.

## Reflection

The gap between spec and implementation isn't a failure of planning — it's the nature of building something new. The spec got the vision right (agent-first, content over pixels, CLI-driven). What it couldn't anticipate was how the details would change once real inputs hit the system.

Keeping the original spec in `learnings/2026-02-13-0.md` lets us see both: what we intended and what we learned. The rewritten CLAUD.md is now a living document that describes what the code actually does, not what we hoped it would do.
